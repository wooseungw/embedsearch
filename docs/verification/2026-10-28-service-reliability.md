# EmbedSearch 보완 및 검증 — 2026-10-28

작업 브랜치: `fix/service-reliability`. 시작 시 존재하던 10개 파일의 변경을 보존했다. 새 의존성, 커밋, 원격 푸시, 설치된 사용자 앱 교체는 하지 않았다. 초기 diff와 실행 로그/JSON은 로컬 `.omx/plans/service-reliability-work/`에 있다.

## 변경 내용

- `App/Actions/Shell.swift`: 두 출력 스트림을 실행 중 소진하고 각각 최초 1 MiB만 보관한다. 제한시간·작업 취소 시 직접 자식을 종료하고 회수한다. 직접 자식이 끝난 뒤 상속된 pipe를 잡고 있는 후손 때문에 반환이 지연되지 않도록 비차단 읽기를 사용한다. 후손 프로세스 전체를 종료·회수한다는 보장은 하지 않는다.
- `Sources/SearchCore/Engine/SearchEngine.swift`, `Store/IndexStore.swift`: v9 마이그레이션으로 실패 종류/횟수/시각을 저장한다. 일시적 추론 실패는 최초 시도를 포함해 최대 3회 시도하며, 기본 600초 간격에서 지수적으로 재시도한다. 영구적인 읽기 오류는 파일 변경 또는 수동 재색인을 기다린다. 메뉴·설정 전체 재색인과 폴더별 재색인은 실제 캐시를 무효화하며 공유 버전의 다른 경로도 함께 갱신한다.
- `App/Settings/`, `App/Search/EngineRuntime.swift`: 로컬 검색 이력 저장·개인화, 7/30/90/365일 보관, 전체 삭제를 연결했다. 기본은 30일이다. 삭제 시 DB와 엔진 캐시를 함께 지우며, 삭제 전에 시작한 질의가 완료되어도 기록을 복원하지 않는다. 저장 중지는 새 선택 이력과 디스크 질의 캐시의 기록을 막는다.
- `Sources/SearchCore/Ranking/`: 최고 글자 점수 0.75 미만의 혼합 질의에서 약한 글자 증거를 낮춘다. 순수 초성 질의는 제외한다. 파일 목록이 있으면 파일 점수와의 기존 척도를 보존한다. `--fixed-fusion`으로 이전 점수 정책을 비교할 수 있다.
- `Sources/SearchCore/Eval/Evaluation.swift`, `Sources/EmbedSearchCLI/SearchCommands.swift`: 실행 예외와 모델 사용 불가를 일반적인 검색 실패와 분리한다. 정답 없음 질의를 지원하고 `eval --json`으로 질의별 정답 순위, 상위 결과, 예외, 데이터/모델 fingerprint와 전체 ranking 설정을 저장한다.
- `tools/eval/`: 원본 합성 PDF 30개와 OCR 카드 이미지 10개, 개발 72문항·검증 39문항을 생성한다. 같은 파일의 표현 변형은 같은 분할에 둔다. 비교 도구는 다른 코퍼스/질의/모델의 결과 비교를 거부한다.

## 실제 모델 평가

같은 로컬 MLX 체크포인트, 768차원, 고정 색인, 개인화 비활성화 조건이다. 앱 154개·설정 762개·명령 22개의 938개 항목을 사용했다. 기본 평가셋의 단축어 두 문항은 대상이 없어 실패로 포함됐다. 기존 120문항은 이전부터 조정에 사용한 회귀셋이며 새 held-out 결과로 표현하지 않는다.

|---|---:|---:|
| 혼합 MRR@10 | 0.8925 | 0.9500 |
| 정답 1위 | 100/120 | 110/120 |
| 설명형 정답 1위 | 9/17 | 16/17 |
| 정확한 이름 정답 1위 | 39/43 | 39/43 |

동일한 합성 파일 40개를 추가한 978개 항목에서도 기존 앱/설정/명령 120문항의 비교 결과는 동일했다. 새 합성 파일 평가에서는 다음 결과를 얻었다. PDFKit과 실제 텍스트·이미지 모델을 사용했다. 새 검증 결과를 보고 융합 설정을 다시 조정하지 않았다.

합성 데이터는 파이프라인 회귀 검사다. 실제 사진이나 사용자 문서에 대한 대표 성능으로 일반화하지 않는다. 파일 검색은 hybrid 경로에서 평가하며 semantic 모드는 항목 카드 벡터만 평가한다.

## 캐시 검색 지연

빌드/테스트 종료 후 고정·변경 정책을 교대로 3회씩 실행했다. 각 실행의 semantic pass가 채운 질의 캐시를 hybrid pass가 사용했으며 정책별 360개 측정치를 합산했다.

| CLI 캐시 hybrid 경로 | 고정 융합 | 변경 후 |
|---|---:|---:|
| p50 | 3.229 ms | 3.224 ms |
| p95 | 6.332 ms | 6.238 ms |

이 실행에서는 제안한 p95 +10% 회귀 한도 안에 있었다. 미세한 차이를 유의한 속도 향상으로 해석하지 않는다. 모델 미로드 첫 검색이나 UI debounce가 포함된 측정은 아니다. 원자료는 `latency-summary.json` 및 정책별 3개 JSON에 있다.

## 판단과 제한

- 전역 가중치만 조정한 후보는 기존 행 분할 비교의 반대쪽 MRR이 0.925→0.904로 하락해 채택하지 않았다. 신뢰도에 따라 약한 글자 점수를 조정하는 후보를 채택했다.
- 기존 오타 질의 `dispaly settings`는 1위에서 2위로 내려갔다. 오타 유형 전체의 1위 수는 8/9로 유지됐지만 개별 회귀를 숨기지 않는다.
- 새 파일 검증셋의 남은 실패는 사워도우 관련 한국어 질의 미검출, 식별자 `FIELDNOTE8127`의 정답 2위, 정답 없음 질의의 오탐이다. 기존·변경 후 모두 동일하다.
- 합성 OCR 카드 외 자연 사진, opendataloader-pdf 경로, 최소 지원 macOS 15 실기기, 서명된 Sparkle 업데이트 설치는 이번에 검증하지 않았다. 로컬 서명 검증은 공증이나 실제 업데이트 설치 성공을 뜻하지 않는다.
- 실제 모델이 미로드된 상태의 UI 전체 지연과 장시간 메모리/배터리 사용도 별도 측정이 필요하다. CLI 캐시 지연은 UI의 200ms debounce를 포함하지 않는다.
- 독립 하위 에이전트는 계정에서 지원하지 않는 `gpt-5.5` 역할 설정 오류로 실행되지 않았다. 직접 별도 diff 검토를 수행했으며 독립 검토를 받았다고 주장하지 않는다.

설치·원격 배포·병합은 실행하지 않았다. 변경과 테스트, 재현 자료는 현재 작업 브랜치에 남겨 두었다.
